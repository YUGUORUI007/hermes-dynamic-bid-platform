# GOAL：Hermes 驱动的动态投标项目平台

版本：v1.0  
日期：2026-07-21  
状态：实施基线，前端原型确认后锁定

## 1. 最终目标

交付一套可部署、可维护、可验证的完整源码，使用户能够让 Hermes 将任意招标文件或文字信息整理为动态项目内容，在用户确认后通过 Hermes Skill 安全写入平台；平台以统一设计语言展示不同项目的非固定字段，并继续提供项目管理、状态跟踪、权限、审计和归档能力。

## 2. 完成定义

只有同时满足以下条件，GOAL 才算完成：

- 正式网站不依赖内置 LLM 或 OCR 完成核心工作流。
- 动态内容协议、数据库、API、Hermes Skill 和前端渲染形成闭环。
- 新建、查询、查重、更新、状态变更、跟进和归档均可通过 API 完成。
- Hermes Skill 在所有正式写入前执行明确确认步骤。
- 用户确认的 HTML 原型已一比一复刻到真实 Jinja2 页面。
- 现有数据具有可执行迁移路径，迁移过程不静默丢失数据。
- 自动化测试、视觉验证、安全检查和部署文档全部通过。
- 仓库内不包含真实密码、API Key、访问 Token 或可用生产凭证。

## 4. 实施阶段

### G1：产品与视觉基线

- 完成需求文档和本 GOAL 文档。
- 交付独立 HTML 原型，覆盖工作台、全部项目、日程、动态项目详情、动态编辑器、归档、Hermes/API 设置、成员权限、审计日志、基础设置和登录页。
- 所有页面必须使用同一应用骨架、设计 tokens、导航、表格、表单、状态和响应式规则，不允许只重做首页。
- 使用真实业务密度的模拟数据展示不同项目的不同结构。
- 完成桌面与移动端视觉检查。
- 用户确认信息架构、配色、密度和交互方向。

通过门槛：用户明确确认原型，或给出需要修改的具体反馈。

### G2：动态领域模型

- 定义版本化 JSON Schema。
- 将固定业务字段收缩为最小系统外壳。
- 建立 project content、版本、Token、幂等请求和审计模型。
- 编写并验证旧数据迁移脚本。

通过门槛：迁移测试覆盖空数据、正常数据、异常旧数据和重复执行。

### G3：API 与安全

- 实现 Schema、校验、项目 CRUD、搜索、跟进、状态和归档接口。
- 实现 Token Scope、限流、幂等、乐观锁、输入限制和统一错误。
- OpenAPI 示例可直接用于联调。

通过门槛：API 集成测试覆盖成功、未授权、越权、重复提交、版本冲突和恶意输入。

### G4：Hermes Skill

- 建立可安装的 Hermes Skill。
- 写入操作强制执行“生成预览 → 用户确认 → 调用 API”。
- 支持新建、搜索、更新、追加跟进、变更状态和归档。
- 提供环境变量模板和最小权限配置。

通过门槛：使用样例材料完成一次新建和一次增量更新，审计链完整。

### G5：前端一比一复刻

- 将确认后的 HTML 原型拆分为 Jinja2 模板、CSS 和 JavaScript。
- 工作台和详情页全部使用动态数据渲染。
- 完成动态编辑器、空状态、加载状态、错误状态和权限状态。
- 保留可用的用户、审计、归档和设置功能。

通过门槛：关键页面与确认原型在标准视口下保持一致，交互无回归。

### G6：清理、验证与交付

- 停用或删除不再需要的站内 AI/OCR 入口和依赖。
- 清理默认凭证、历史部署敏感信息和无效代码路径。
- 完成测试、可访问性检查、视觉截图和生产验收脚本。
- 更新部署与回滚文档。

通过门槛：全套自动化检查通过，生产式启动成功，健康检查和核心业务闭环通过。

## 5. 工程质量标准

- 后端业务逻辑、数据访问和路由职责清晰，不把所有新逻辑继续堆入单一模块。
- Schema 版本向后兼容；破坏性变化必须升级主版本并提供迁移器。
- API 返回稳定错误代码，不要求 Hermes 解析自然语言判断错误类型。
- 所有数据库写入具备事务边界。
- 动态内容统一服务端校验与前端安全渲染。
- 测试不依赖真实生产服务、真实 Hermes 或真实凭证。
- 新增代码具有类型标注，复杂边界有简短说明。

## 6. 前端质量标准

- 视觉：专业、克制、信息密集但可扫描，不使用营销页结构或 AI 紫色渐变。
- 布局：1440px、1024px、768px、375px 均可用，无不合理横向滚动。
- 交互：点击反馈在 100ms 内出现，常规过渡 150–250ms。
- 可访问性：正文对比度不低于 4.5:1，焦点清晰，图标按钮有标签。
- 稳定性：动态长文本、长字段名、空 section、大表格不会破坏页面结构。
- 一致性：颜色、间距、圆角、字体、图标和状态语义来自统一 tokens。

## 7. 测试矩阵

- 单元测试：Schema 校验、动态 block 规范化、权限、幂等、版本冲突。
- 集成测试：API 全流程、数据库事务、审计记录、归档。
- 迁移测试：旧库副本迁移和重复迁移。
- E2E：管理员登录、Hermes Token 写入、工作台查看、人工编辑、归档。
- 安全测试：XSS、危险 URL、超长载荷、未授权访问、Scope 越权。
- 视觉测试：桌面和移动端截图、文本溢出、弹层遮挡和空状态。

## 8. 最终验收脚本

最终验收必须自动完成：

1. 创建临时用户和最小权限 Token。
2. 校验一个包含自定义 section、表格、时间线和警告的项目载荷。
3. 使用幂等键创建项目并验证重复请求不重复创建。
4. 查询项目并核对动态内容。
5. 使用正确版本更新内容，再使用旧版本验证冲突。
6. 在浏览器检查工作台和详情页。
7. 追加跟进、修改状态并归档。
8. 核对审计记录并清理临时验收数据。

## 9. 约束与决策记录

- 动态不等于任意代码：Hermes 只能提交平台支持的结构化 blocks。
- 项目名称与生命周期状态保留为系统字段，否则无法可靠搜索和管理。
- 用户确认是 Hermes 工作流的强制步骤，API 仍以幂等、权限和审计作为第二道保护。
- 第一版沿用 FastAPI、SQLAlchemy、Jinja2 和服务端渲染，控制改造成本。
- 数据量未达到迁移阈值前可继续使用 SQLite，但模型和事务设计不得阻碍后续 PostgreSQL 迁移。
